# STACK-Δ 위협 모델

## 보호 대상

- 사용자 인증정보와 비밀 환경변수
- 사용자 홈과 프로젝트 외부 파일
- 설치 호스트의 프로세스·지속성 설정
- 분석 결과의 무결성
- 기대 행위 정책의 재현성

## 가정한 공격자

공격자는 npm 패키지의 코드, 설치 스크립트, README, `package.json`을 통제합니다. 다음을 시도할 수 있습니다.

- 정적 시그니처를 피하는 난독화
- 설치 시점의 파일·비밀·프로세스 탐색
- 외부 서버 연결과 2단계 로더
- 백그라운드·지연 실행
- README 프롬프트 인젝션으로 기대 행위 확장
- 컨테이너·계측 환경 감지

## 신뢰 경계

| 구성요소 | 신뢰 수준 | 원칙 |
|---|---|---|
| README·패키지 코드 | 비신뢰 | 명령이 아닌 데이터로만 처리 |
| LLM 추출 결과 | 부분 신뢰 | 근거·스키마 검사 후 정책에 전달 |
| 고정 정책 | 신뢰 | 버전 관리·평가 전 동결 |
| 계측 로그 | 부분 신뢰 | 센서 누락·회피 가능성을 명시 |
| 호스트 | 보호 대상 | 패키지에 직접 노출하지 않음 |

## 방어 불변조건

1. README만으로 비밀·인증정보·지속성 행위를 기대 행위로 만들 수 없습니다.
2. 실제 패키지는 외부 네트워크가 없는 일회용 환경에서만 실행합니다.
3. 실제 자격증명과 개인 홈을 샌드박스에 마운트하지 않습니다.
4. 호스트의 Docker 소켓을 분석 컨테이너에 전달하지 않습니다.
5. LLM 결과는 최종 위험 점수를 직접 바꾸지 않습니다.
6. “관측 없음”을 “안전함”으로 표시하지 않습니다.

## 비목표

- npm 전체 생태계의 완전한 악성 여부 판정
- 모든 네이티브 코드와 커널 수준 회피 탐지
- 실제 공격 인프라와 통신하는 악성코드 실행
- 자동 차단·삭제·신고
